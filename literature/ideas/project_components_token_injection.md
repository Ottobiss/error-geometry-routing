# Адаптивная сегментация: связные компоненты, геометрический селектор и инъекция признаков B2 в B0

Дата: 22 октября 2026. Статус: проект экспериментального протокола, а не описание уже подтверждённых результатов.

## 1. Идея и проверяемые гипотезы

Лёгкая модель L (SegFormer-B0 в дорожном эксперименте) обрабатывает полный кадр. По её ответам выделяем связные компоненты и описываем их уверенность, форму, окружение и геометрию внутренних признаков. Небольшой селектор оценивает ожидаемую пользу дорогой обработки относительно её стоимости. Тяжёлая модель H (SegFormer-B2) получает только выбранные прямоугольные кропы с контекстом.

Рассматриваем два способа использовать H:

1. **Замена предсказаний:** перенести вероятности H обратно в кадр и заменить ответ L в разрешённой области. Это простой контрольный вариант.
2. **Инъекция признаков:** перенести пространственные признаки H в координаты L, привести их к пространству признаков L обучаемым адаптером, смешать в выбранных местах и выполнить уточнение и декодирование в ветке B0. Это основная новая архитектурная идея.

Гипотезы проверяем отдельно:

- геометрия позволяет выбирать полезные обращения к H лучше, чем только уверенность;
- инъекция признаков даёт лучший компромисс качества и полного времени, чем замена вероятностей;
- контекст кропа влияет на исправимость ошибок;
- выигрыш сохраняется при переносе Cityscapes → ACDC без настройки по финальной разметке ACDC.

**Плохое качество заранее неизвестно.** При применении ищем предположительно проблемные компоненты по информации B0; истинные ошибки доступны только при подготовке и оценке.

Компонента, область замены и кроп — разные объекты. Их площади нельзя подставлять друг вместо друга.

## 3. Как строим компоненты и кропы

### 3.1. Предсказанная маска

Для Cityscapes используем многоклассовый ответ:

$$\hat y_L(u)=\arg\max_c p_{L,c}(u).$$

Для каждого класса выделяем восьмисвязные компоненты его маски. Набор классов-кандидатов фиксируем до теста; большая компонента дороги может сделать кроп почти полнокадровым.

Для Severstal — отдельная бинарная маска каждого класса дефекта:

$$M_c(u)=\mathbf1[p_{L,c}(u)>t_c].$$

Пороги t_c настраиваем только на разработочной части. Между каналами возможны перекрытия. Фильтры размера фиксируем явно: удалённая до селектора компонента больше не может быть выбрана. Значение min_size из конкретного ноутбука не считаем автоматически правильным.

### 3.2. Область изменения и контекст

Стартовые варианты:

$$A_K=K\quad\text{или}\quad A_K=\operatorname{dilate}(K,r).$$

$$B_K=\operatorname{clip}_{image}\bigl(\operatorname{expand}(\operatorname{bbox}(A_K),m)\bigr).$$

r — расширение области исправления; m — дополнительный контекст. При A_K=K нельзя добавить пропущенные пиксели за пределами исходной компоненты. Полностью пропущенный объект вообще не создаёт кандидата. Для отдельной расширенной версии можно добавить компоненты карты неопределённости или сетку резервных регионов; это меняет генератор кандидатов и должно оцениваться отдельно.

Из фотографии вырезаем **настоящий прямоугольник с окружением**. Не закрашиваем фон вне компоненты внутри кропа: это лишает H контекста и меняет распределение входа.

Сохраняем преобразование координат: начало кропа, масштаб, padding, размер входа модели. Контекст помогает распознаванию, но сильное уменьшение кропа может уничтожить тонкие объекты. Проверяем размер кропа и масштабирование раздельно.

### 3.3. Пересечения

В первой версии запускаем отдельный кроп на компоненту. Для пересекающихся A_K задаём порядок или усреднение вероятностей/признаков с фиксированными весами; один пиксель не учитываем несколько раз в итоговой маске.

Оптимизация с объединением близких кропов — отдельная политика: после объединения меняются контекст, время и предсказания. Для неё заново собираем цели селектора или проверяем качество переноса старых целей.

## 4. Что получает селектор

Селектор работает после полного прохода L и до запуска H. Вход — X_K, а не ответ B2 и не истинная разметка.

| Группа | Примеры |
|---|---|
| Класс | One-hot класса; для бинарной задачи — канал дефекта |
| Размер и форма | Площадь K, относительная площадь, ширина/высота bbox, заполнение bbox, отношение сторон |
| Уверенность | Средние и квантили энтропии, максимальной вероятности, маржи |
| Структура | Те же оценки отдельно на границе, внутри и в окружении |
| Геометрия | Расстояние до своего/ближайшего прототипа, отрыв конкурента, Trust Score |
| Контекст | Статистики в кольце R_K и доля доступного контекста у края кадра |
| Стоимость | Размер реального тензора B2 после resize/padding, ожидаемое время, число кропов |

$$R_K=\operatorname{dilate}(K,r_{ctx})\setminus K,\qquad
\operatorname{fill}(K)=\frac{|K|}{|\operatorname{bbox}(K)|}.$$

Для многоклассовой задачи:

$$E(u)=-\sum_c p_{L,c}(u)\log(p_{L,c}(u)+\varepsilon),$$
$$VR(u)=1-\max_c p_{L,c}(u),\qquad PM(u)=p_{(1)}(u)-p_{(2)}(u).$$

Высокие E, VR и низкая PM указывают на сомнение модели, но не гарантируют пользу B2. Для независимых бинарных каналов используем бинарную энтропию соответствующего канала.

Пиксельную карту s агрегируем, например:

$$\bar s_K=|K|^{-1}\sum_{u\in K}s(u),\qquad q_{0.9,K}=Q_{0.9}\{s(u):u\in K\}.$$

При переносе K на грубую сетку признаков учитываем долю покрытия токена; иначе маленькая компонента может исчезнуть. Правило взвешивания и обработку пустых регионов фиксируем.

### 4.1. Геометрические признаки

Опорные центры и ковариацию строим только по разрешённой обучающей части; исключаем ignore и контролируем дисбаланс классов.

$$d_c^{E}(z)=\|z-\mu_c\|_2,$$
$$d_c^2(z)=(z-\mu_c)^\top(\widehat\Sigma+\eta I)^{-1}(z-\mu_c).$$

Первая формула — евклидово расстояние. Вторая — регуляризованный квадрат расстояния Махаланобиса: учитывает направления естественного разброса признаков. η — регуляризация ковариации, отдельный параметр от цены вычислений λ.

$$s_{near}(u)=\min_c d_c^2(F_L(u)),\quad s_{pred}(u)=d_{\hat y_L(u)}^2(F_L(u)).$$

Первое показывает нетипичность для всех классов; второе — несоответствие предсказанному классу.

Для банка опорных признаков класса \(\mathcal H_c\):

$$d(z,\mathcal H_c)=\min_{v\in\mathcal H_c}\|z-v\|_2,$$
$$s_{trust}=\log\frac{d(z,\mathcal H_{\hat y})+\varepsilon}{\min_{c\ne\hat y}d(z,\mathcal H_c)+\varepsilon}.$$

Большой s_trust означает, что чужой класс ближе своего. Это адаптация Trust Score, не вероятность ошибки. Для бинарных каналов определяем отдельные состояния «дефект/нет дефекта»; нельзя автоматически переносить argmax многоклассовой формулы.

Гиперболическая ветка — дополнительная абляция, а не обязательный первый шаг. Один явно заданный вариант: нормировать z, фиксированно спроецировать в меньшую размерность v и отобразить в единичный шар:

$$h(v)=\tanh(\alpha\|v\|)\frac{v}{\|v\|},\quad h(0)=0,$$
$$d_{\mathbb H}(a,b)=\operatorname{arcosh}\left(1+\frac{2\|a-b\|^2}{(1-\|a\|^2)(1-\|b\|^2)}\right).$$

α фиксируем на разработочной части; ограничиваем нормы вдали от 1 для устойчивости. Можно брать прототипы-медоиды опорных точек. Сравниваем с евклидовым расстоянием при той же проекции и нормировке: иначе эффект нельзя отнести к метрике. Фиксированное отображение само по себе не доказывает иерархичность признаков.

Статистики по другим изображениям текущего батча без разметки допустимы как отдельная ветка, но тогда результат зависит от состава батча. Основной воспроизводимый baseline использует фиксированный банк.

## 5. Контрольный вариант: замена вероятностей

Для выбранного K запускаем B2 на B_K, убираем padding и переносим вероятности в координаты кадра:

$$\tilde p_{H,K}=\operatorname{WarpBack}(p_H(B_K)).$$

$$p_{mix}(u)=(1-w_K(u))p_L(u)+w_K(u)\tilde p_{H,K}(u).$$

w_K=1 внутри A_K и 0 снаружи для жёсткой замены. Мягкая граница — отдельная абляция. Затем применяем argmax или пороги бинарных каналов. При нескольких кропах используем заранее заданное правило объединения.

Обучаются только селектор и, если явно выбрано, калибровка. L и H заморожены. Этот вариант проверяет маршрутизацию без влияния обучаемого адаптера.

## 6. Основная новая ветка: инъекция токенов B2 в B0

### 6.1. Что означает «заменяем проблемные токены»

Токен здесь — вектор признаков пространственной позиции. Он не равен связной компоненте: компонента включает много пикселей и может пересекать несколько токенов. Кроп — вход B2, а маска M_s — адреса изменения в карте B0.

B0 и B2 обучены независимо: равные координаты векторов не обязаны иметь одинаковый смысл. Размерности стадий тоже различаются. Поэтому сырая подстановка F_H вместо F_L некорректна; необходимы пространственное совмещение и обучаемая проекция.

SegFormer использует несколько масштабов в декодере. Замена только последней стадии оставляет ранние признаки B0; это допустимая абляция, но не эквивалент полной замене представления.

### 6.2. Рекомендуемая точка инъекции

Первая версия: получить все карты B0, инъектировать признаки выбранной поздней стадии перед декодером, оставить остальные стадии B0. После смешивания добавить небольшой residual-модуль уточнения и запустить декодер B0.

Если компоненты получаем из финальной маски B0, первый декодер уже был выполнен. После инъекции потребуется повторное декодирование, и его время обязательно учитываем. Для кадров без выбранных регионов возвращаем исходный ответ без второго прохода.

«Ещё пара слоёв» — новый модуль, который нужно описать и обучить. Если вместо него повторно используем исходные блоки B0, явно указываем точку входа и какие блоки исполняются второй раз. Инъекция внутрь энкодера потребует пересчёта всех последующих стадий.

### 6.3. Совмещение и формулы

На стадии s:

$$F_L^s\in\mathbb R^{h_s\times w_s\times d_L^s},\quad F_{H,K}^s\in\mathbb R^{h_{K,s}\times w_{K,s}\times d_H^s}.$$

Приводим признаки B2 к каналам B0:

$$U_{K,s}=P_s(F_{H,K}^s),\qquad P_s:\mathbb R^{d_H^s}\to\mathbb R^{d_L^s}.$$

P_s — обучаемая линейная проекция, например 1×1 convolution с нормировкой. Пространственно переносим в сетку полного кадра:

$$\widetilde U_{K,s}=\operatorname{WarpBack}_s(U_{K,s}).$$

WarpBack учитывает кроп, resize, padding, stride и центры ячеек. Интерполяция совмещает координаты, но не восстанавливает потерянный глобальный контекст и не делает признаки кропа равными признакам полного кадра.

Для единственного выбранного региона:

$$F_{mix}^s=(1-M_s)\odot F_L^s+M_s\odot\widetilde U_{K,s},$$
$$F_{out}^s=F_{mix}^s+M_s\odot Q_s(F_{mix}^s),$$
$$p_{inj}=D_L(F_L^1,\ldots,F_{out}^s,\ldots,F_L^4).$$

M_s — проекция области A_K на сетку признаков; может задавать долю покрытия. Q_s — небольшой обучаемый residual-модуль, например два свёрточных слоя с нелинейностью. Он учит совместную обработку смешанных признаков. Формула с маской ограничивает добавку Q_s, но декодер и интерполяция всё равно могут менять соседние пиксели.

Для нескольких регионов сначала строим единую карту внедряемых признаков с нормированными весами перекрытия. Нельзя независимо присвоить одному токену несколько несовместимых векторов.

Если требуется строго сохранять ответ вне A=∪A_K, финально смешиваем p_inj с p_L по маске A. Тогда польза определяется именно этим ограниченным действием. Без финального ограничения оцениваем изменения по всему кадру, включая возможный вред вне компонентов.

### 6.4. Маскирование не равно экономии

| Способ запуска B2 | Что происходит с затратами |
|---|---|
| Полный кадр, остальные пиксели занулены | Обычная плотная модель всё равно считает полный тензор; экономия не следует из маски |
| Полный кадр, затем выбираем нужные токены | Полный энкодер B2 уже оплачен; полезно как диагностический ориентир |
| Реальные кропы с контекстом | Экономия возможна, зависит от размеров входа, числа запусков и batching |
| Реальное пропускание токенов | Нужна отдельная реализация разреженного attention и пространственных операций |

Для первого рабочего варианта выбираем кропы. Нельзя просто удалить произвольные токены из стандартного SegFormer и считать, что остальные операции корректно работают: требуется сохранить пространственную структуру и контекст.

### 6.5. Что обучается

| Блок | Первая версия инъекции |
|---|---|
| Энкодер B0 и исходный декодер | Заморожены |
| Энкодер B2 | Заморожен; для инъекции его сегментационный декодер может не требоваться |
| Проекции P_s и уточнение Q_s | Обучаются |
| Селектор | Обучается отдельно после фиксации действия инъекции |

Замороженный декодер пропускает градиенты к P_s и Q_s, хотя его веса не меняются. Затем отдельной абляцией можно разморозить декодер; это уже дополнительные обучаемые параметры.

Фраза «вернуть распределение» означает обучить совместимость представлений по задаче сегментации, а не гарантированно восстановить прежнее распределение математически.

### 6.6. Обучение адаптера и порядок работ

1. На обучающей части генерируем компоненты B0 и разные наборы выбранных регионов, включая пустой набор и разные бюджеты. Не используем финальную тестовую разметку.
2. Прогоняем B2 на кропах с той же политикой контекста, что при применении.
3. Обучаем P_s и Q_s по финальному предсказанию инъекционной системы.
4. Фиксируем систему инъекции, затем собираем истинную пользу для обучения селектора.
5. Обучаем селектор и на отдельной части выбираем бюджет/λ.

Пример функции обучения адаптера:

$$\mathcal L_{adapt}=\mathcal L_{seg}(p_{inj},y)+\beta\mathcal L_{keep},$$
$$\mathcal L_{keep}=\frac1{|V\setminus A|}\sum_{u\in V\setminus A}\mathrm{KL}(p_L(u)\|p_{inj}(u)).$$

V — валидные пиксели без ignore. Первый член — CE для многоклассовой задачи или BCE и согласованная Dice-loss для независимых каналов. Второй поощряет сохранение ответа вне выбранных областей; при пустом знаменателе задаём его равным нулю. β выбираем по validation. Для бинарных каналов используем KL Бернулли или другую явно заданную меру.

Если адаптер изменился, изменилось действие эксперта: старые G_K больше не считаем точной целью. Пересобираем цели или явно измеряем их устаревание. Сначала не обучаем селектор и адаптер совместно — это усложняет проверку причин выигрыша.

## 7. Как определяем пользу компоненты

### 7.1. Аддитивная польза по ошибкам

Пусть V — валидная область кадра, N=|V|. Для действия замены в A_K:

$$C_L(K)=\frac1N\sum_{u\in A_K\cap V}\mathbf1[\hat y_L(u)\ne y(u)],$$
$$C_H(K)=\frac1N\sum_{u\in A_K\cap V}\mathbf1[\hat y_{H,B_K}(u)\ne y(u)],$$
$$G_K=C_L(K)-C_H(K).$$

G_K>0 — исправлено больше пикселей, чем испорчено. Нормировка на N сохраняет вклад площади. Если среднее улучшение внутри A_K равно δ_K, то G_K=(|A_K∩V|/N)δ_K. Повторно умножать G_K на площадь нельзя.

Нормировка на |A_K∩V| отвечает другому вопросу: улучшение на один пиксель области. Она приравнивает маленькие и большие области при одинаковой доле исправлений.

Для Severstal считаем ошибки соответствующего бинарного канала; если действие меняет все каналы, цель должна учитывать все изменённые каналы.

### 7.2. Польза инъекции и неаддитивность

При инъекции полезно оценивать реальное конечное действие на полном кадре:

$$G_K^{inj}=\ell(p_L,y)-\ell(p_{inj,\{K\}},y).$$

ℓ — заранее выбранная ошибка по всему кадру. Так учитываем воздействие на соседние пиксели. Можно отдельно разложить изменение внутри и снаружи A_K.

Из-за взаимодействия токенов, перекрытий и декодера обычно:

$$G(S)\ne\sum_{K\in S}G_K^{inj}.$$

Оценка по одному K — приближение для селектора. Итоговое качество всегда измеряем для реально совместно выбранного набора S. При сильных взаимодействиях собираем цели условного добавления K к набору S или выбираем регионы последовательно; это следующий этап.

### 7.3. Dice и IoU — отдельные цели

$$Dice_c=\frac{2TP_c}{2TP_c+FP_c+FN_c},\qquad
IoU_c=\frac{TP_c}{TP_c+FP_c+FN_c}.$$

Для Severstal фиксируем правила усреднения по каналам/изображениям и обработку пустых масок. Для Cityscapes основной результат — mIoU по классам с установленными ignore-правилами. Нельзя смешивать среднее по изображениям с IoU из общей матрицы ошибок.

Можно учить G_K как изменение Dice или mIoU полного результата после одного действия. Тогда цель лучше связана с отчётной метрикой, но неаддитивна. В первом эксперименте отделяем простую цель по пиксельным ошибкам от итоговых Dice/mIoU и измеряем, насколько первая подходит для второй.

## 8. Модель и обучение селектора

### 8.1. Удобный первый вариант — регрессия пользы

$$\widehat G_K=S_\theta(X_K),\qquad
\mathcal L_{sel}=\frac1M\sum_K(\widehat G_K-G_K)^2.$$

Начинаем с линейной регрессии с регуляризацией. Альтернативы — небольшой бустинг или MLP d→32→1 с ReLU; архитектура одинакова в сравнениях признаков. Для MSE оптимальная функция оценивает условное среднее пользы. Huber-loss можно проверить на выбросах, но её оптимум не обязан быть тем же условным средним.

Числовые признаки стандартизируем по train; класс кодируем one-hot. Линейная регрессия пользы не равна логистической регрессии вероятности полезности. Простая классификация G_K>0 теряет величину выигрыша.

### 8.2. Связь со статьёй Narasimhan et al., 2022

Источник: *Post-hoc Estimators for Learning to Defer to an Expert*, §4.2, формулы (13)–(15), рис. 3.

Из статьи берём разделение на фиксированную базовую модель и отдельно обучаемое правило передачи, сравнивающее стоимость двух действий. В статье задача классификации; компоненты, кропы, метрики сегментации и инъекция токенов — наша адаптация. Теоретические гарантии статьи не переносим автоматически.

Адаптация cost-sensitive rejector:

$$a_K=C_L(K),\qquad b_K=C_H(K)+\lambda T_K,$$
$$\mathcal L_K=a_K\log(1+e^{-r_\theta(X_K)})+b_K\log(1+e^{r_\theta(X_K)}).$$

Положительный r выбирает дорогую ветку. Первый член повышает score, когда дорого оставить L; второй снижает его, когда дорого обращаться к H. Стоимости должны быть неотрицательны. Если обе нулевые, пример не даёт сигнала.

При изменении λ в этой функции потерь обычно заново обучаем rejector. Это отличается от регрессии G, где λ меняем после обучения. При переменной стоимости из-за объединения кропов простая цена отдельной компоненты может быть лишь приближением.

## 9. Площадь и затраты

### 9.1. Какие площади записываем

$$a_K=|K|/(HW),\qquad a_A=|A_K|/(HW),\qquad a_B=|B_K|/(HW).$$

Это геометрические доли, не время. Если B2 получает тензор размера h'_K×w'_K после resize/padding, для вычислений важен именно он. В этом разделе a_K — площадь; во избежание конфликта в коде используем area_component, а стоимость из §8 называем cost_keep.

При фиксированном входе B2 каждый кроп имеет примерно одинаковую вычислительную стоимость независимо от исходной площади. При переменном входе зависимость от площади измеряем: attention, padding, аппаратная загрузка и batching мешают считать время строго пропорциональным пикселям.

### 9.2. Время контрольного каскада

$$T_{mask}(x,S)=T_L^{full}+T_{CC}+T_{geom}+T_{sel}+T_{crop}(S)+T_H^{seg}(S)+T_{stitch}(S).$$

Здесь CC — компоненты и их характеристики; geom — извлечение геометрии; crop — подготовка кропов; seg — энкодер и декодер B2; stitch — перенос и сборка. Это схема учёта; при перекрытии операций итоговое wall-clock измеряем непосредственно, а не только суммируем отдельные таймеры.

### 9.3. Время инъекции

Для непустого S:

$$T_{inj}(x,S)=T_L^{full}+T_{CC}+T_{geom}+T_{sel}+T_{crop}(S)+T_H^{enc}(S)+T_{align}(S)+T_{P,Q}+T_{D_L}^{repeat}+T_{final}.$$

T_L^full уже включает первый декодер, нужный для маски и компонент. Повторный декодер, адаптер, перенос признаков и сборка — реальные дополнительные затраты. Для S=∅ возвращаем исходный ответ без необязательных блоков. Если алгоритм запускает B2-декодер и для инъекции, его тоже учитываем.

Время адаптера может зависеть от площади полного кадра, если Q выполняется плотной операцией на всей карте. Маска в формуле не делает вычисление Q автоматически разреженным.

### 9.4. Стоимость компоненты и набора

В простом режиме отдельных последовательных кропов:

$$\widehat T_K=f(h'_K,w'_K,\text{dtype, device, batch policy}).$$

f строим по измерениям размеров на train/calibration: таблица или простая регрессия. Прогноз доступен до запуска B2. Не используем фактическое ещё не измеренное время будущего запуска как вход онлайн-селектора.

Если используем batching или объединение:

$$T(S)\ne\sum_{K\in S}T_K.$$

Более корректна предельная стоимость:

$$\Delta T(K\mid S)=T(S\cup\{K\})-T(S).$$

Её можно приближать планировщиком. Для первого baseline фиксируем простую политику, затем измеряем фактическое полное время.

Также записываем FLOPs/MACs с указанием соглашения, peak GPU memory, количество кропов, сумму площадей входных тензоров и площадь их объединения. Последние две отличаются при перекрытиях. FLOPs — вспомогательная характеристика, не замена задержке.

## 10. Как выбираем λ и порог

### 10.1. Правило для регрессии пользы

$$\text{выбрать }K\iff\widehat G_K>\lambda\widehat T_K.$$

Если G — доля исправленных ошибок, T — миллисекунды, λ имеет единицы «доля ошибок на миллисекунду». Это не количество пунктов Dice за миллисекунду, если цель не Dice. При переходе от мс к секундам численное значение λ меняется.

Эквивалентно для положительного времени: \(\widehat G_K/\widehat T_K>\lambda\). При λ≥0 отрицательная предсказанная польза не выбирается. При фиксированном T это обычный порог пользы; при разном T порог зависит от стоимости кандидата.

### 10.2. Настройка под средний бюджет

1. Задаём полный бюджет b, например условные 25 мс на кадр. Это иллюстрация, не замер проекта.
2. Фиксируем модели, адаптер, генератор компонентов и предобработку.
3. На validation перебираем λ, включая режим без H и режим всех кандидатов.
4. Для каждого λ запускаем реальный конвейер, получаем качество Q_val(λ) и среднее полное время T̄_val(λ).
5. Выбираем:

$$\lambda^*=\arg\max_{\lambda:\ \bar T_{val}(\lambda)\le b}Q_{val}(\lambda).$$

Если несколько вариантов равны, выбираем более быстрый по заранее заданному правилу. Если даже обязательный проход B0 с маршрутизацией превышает b, допустимой точки нет; λ это не исправит. Для p95-бюджета оптимизируем p95, а не среднее.

Для фиксированных независимых прогнозов решения меняются при пересечении отношений \(\widehat G_K/\widehat T_K\); кандидаты λ можно брать из них. Реальное время и качество не обязаны быть монотонны из-за batching, шума и взаимодействий.

При линейной цене λ решает лагранжев вариант задачи качества/стоимости. Из-за дискретных действий не любая бюджетная точка достижима одним λ. При жёстком лимите на кадр нужен дополнительный планировщик: выбирать набор S с учётом бюджета, стоимости и взаимодействий. Простая сортировка по G/T — эвристика, не точное решение произвольной задачи рюкзака.

После выбора фиксируем λ и оцениваем test. При сдвиге домена бюджет может нарушаться: меняется число и размер компонент. Если нужен строгий лимит, добавляем ограничитель вычислений и тестируем его как часть системы.

### 10.3. Порог и λ — не одно и то же во всех схемах

- Регрессия G: обучаем один раз, λ настраиваем после обучения.
- Cost-sensitive rejector: λ входит в обучение; для сетки λ переобучаем селектор.
- Чистый score с порогом τ: τ выбираем по validation и полному времени; score не обязательно измеряет пользу в физических единицах.

Численный одинаковый τ для разных селекторов не обеспечивает одинаковые затраты. Доля выбранных компонент тоже не обеспечивает одинаковый бюджет.

## 11. Разделение данных и отсутствие утечки

Разделяем по изображениям, а при связанных сценах — по сценам/последовательностям, а не по компонентам одного кадра:

1. Данные исходного обучения сегментаторов.
2. Обучающая часть проекта: опорный банк и адаптер. При малом объёме используем внутренние разбиения/cross-fitting.
3. Обучение селектора на зафиксированном действии; собираем X_K и G_K для всех доступных кандидатов, а не только уже выбранных.
4. Validation для контекста, архитектуры, λ и порогов.
5. Независимый test, открываемый после фиксации решений.

Необходимость разметки на подготовке не означает её доступность при маршрутизации. В runtime селектор использует только B0, геометрию из зафиксированных статистик и стоимость будущего кропа.

Для Cityscapes → ACDC фиксируем все параметры на Cityscapes, затем оцениваем по условиям ACDC. Донастройка на ACDC — отдельный supervised/adaptation-режим с собственными train/validation/test, не zero-shot перенос. Severstal — отдельная задача с собственными моделями и селектором; веса дефектных моделей на дорожные сцены не переносим.

## 12. Что измеряем

### 12.1. Качество

- B0 и B2 на полном кадре как обязательные ориентиры.
- Итоговые mIoU для дорог; Dice для дефектов с фиксированным протоколом.
- Изменение качества относительно B0 и разрыв до полного B2. Каскад не обязан лежать строго между ними.
- Отдельно внутри выбранных областей, на границах и вне областей.
- Доля вредных обращений; суммарные исправленные и испорченные пиксели; калибровка прогноза G.
- AUROC/AP обнаружения ошибок и полезных обращений — вспомогательные метрики. Они не заменяют качество каскада.
- Для инъекции сравниваем одиночные и совместные вмешательства, проверяя неаддитивность.
- На ACDC — каждое условие отдельно и итоговое агрегирование.

### 12.2. Время и ресурсы

Фиксируем GPU/CPU, библиотеки, входное разрешение, dtype, batch size, policy padding, режим eval и отключение градиентов. Перед измерением прогреваем модель. Для GPU используем корректную синхронизацию или CUDA events; отдельно измеряем end-to-end wall-clock с подготовкой и сборкой, чтобы не потерять CPU и передачи данных.

Публикуем среднее, медиану, p95, разброс повторов, peak memory и throughput при явно указанном batching. Задержка одного кадра и throughput батча — разные показатели. Не включаем разовые скачивания и загрузку весов в steady-state inference; cold start при необходимости измеряем отдельно.

Даталоадер/диск либо включаем во все сравнения, либо исключаем во всех и явно описываем. Сохраняем промежуточные признаки B0 на устройстве при инъекции, учитывая память. Если выгружаем их, измеряем перенос.

### 12.3. Обязательные кривые

Строим качество–полное время для нескольких λ/бюджетов. На графике отмечаем B0, полный B2, случайный выбор, уверенность, геометрию и оракульный ориентир. Выигрыш в качестве при равном числе компонент недостаточен: сравниваем при сопоставимом полном времени.

Доверительные интервалы считаем по изображениям или последовательностям, а не считаем коррелированные пиксели независимыми наблюдениями. Для обучаемых модулей используем несколько seed, если ресурсы позволяют.

## 13. План сравнений и абляций

| Вариант | Что проверяет |
|---|---|
| Только B0 | Минимальные обязательные затраты |
| Полный B2 | Качество и время дорогого независимого решения |
| Случайные компоненты при сопоставимом времени | Нужен ли информативный селектор |
| Уверенность + класс/форма/контекст/стоимость | Основной честный baseline |
| То же + евклидова геометрия | Дополнительная информация внутренних признаков |
| То же + Махаланобис / Trust Score | Польза структуры опорного пространства |
| То же + гиперболическая геометрия | Добавочная польза выбранной метрики |
| Оракул по истинному G | Диагностика потенциала кандидатов; не применимый метод |
| Замена вероятностей vs инъекция | Полезен ли обмен внутренними представлениями |
| Инъекция с oracle-регионами | Способен ли адаптер вообще извлекать пользу |
| Адаптер без B2 / с признаками B0 | Не объясняется ли выигрыш добавленными слоями и обучением |
| Одна поздняя стадия vs несколько | Какая глубина обмена нужна |
| Разные m и r | Контекст против площади исправления |
| B2-кроп vs B2-полный кадр, одна область оценки | Потеря контекста/масштаба |
| Финальная маска ограничения vs без неё | Локальность и побочные изменения |
| Замороженный vs обучаемый декодер B0 | Цена дополнительной адаптации |

В сравнении признаков фиксируем компоненты, кропы, контекст, модели, адаптер, доступную разметку и семейство селектора. Подбор сложности проводим сопоставимо. При сравнении разных действий можно обучать отдельные селекторы, поскольку польза замены масок и инъекции различается; дополнительно полезно сравнить действия на одном фиксированном наборе регионов.

Оракул одиночных выгод не гарантирует оптимальность совместного набора при инъекции; подписываем его именно как ориентир по одиночным действиям.

## 14. Минимальный порядок реализации

1. Проверить чекпоинты, классы, предобработку, качество и время B0/B2 на полном кадре.
2. Реализовать компоненты, A_K, B_K, обратный перенос и сборку. Визуально проверить координаты, тонкие объекты, края и перекрытия.
3. Получить реальную пользу B2 на кропах и диагностировать влияние контекста.
4. Реализовать замену вероятностей, линейный селектор и таблицу времени по реальным входным размерам.
5. Сравнить уверенность и геометрию при равном времени.
6. Реализовать одну точку инъекции, P_s, Q_s и повторный декодер. Проверить пустую маску, выравнивание и совместимость форм тензоров.
7. Обучить адаптер; проверить oracle-регионы и контроль «дополнительные слои без B2».
8. Зафиксировать адаптер, пересобрать цели пользы, обучить селектор для инъекции.
9. Настроить λ на validation, измерить полный pipeline на test.
10. После основной версии проверить несколько стадий, объединение кропов и перенос на ACDC.

Это порядок экспериментов по компонентам. Переключение целых изображений можно оставить диагностическим baseline, но оно не подменяет выбранную единицу решения.

## 17. Подробная рабочая спецификация: от обучения B0 до выбора компонент

Этот раздел фиксирует конкретную первую реализацию и уточняет порядок обучения. **Полное дообучение лёгкой модели на сегментацию и обучение селектора — два разных этапа.** Если подходящий B0 уже обучен на целевой задаче, первый этап можно не повторять. Если выбираем режим «обучаем полностью лёгкую модель», выполняем этап 17.1, затем фиксируем полученный checkpoint. В экспериментах post-hoc селектора не продолжаем незаметно менять B0.

### 17.1. Полностью дообучаем лёгкую модель

B0 состоит из четырёх стадий энкодера, многомасштабного декодера и последнего классификатора. Полное дообучение означает, что обновляются **все** эти блоки, а не только последний слой. Обычно стартуем с предобученного checkpoint, согласуем число классов и дообучаем на train целевой задачи.

Для многоклассовой сегментации:

$$p_L(x)=\operatorname{softmax}(Z_L(x)),$$
$$\mathcal L_{B0}=-\frac1{|V|}\sum_{u\in V}\log p_{L,y(u)}(u).$$

Z_L — логиты, то есть числа до softmax; V — пиксели с допустимой разметкой. Производная ошибки проходит через классификатор, декодер и все стадии энкодера. Для независимых каналов Severstal используем sigmoid и BCE, при необходимости добавляем Dice-loss с явно зафиксированными весами.

Разделение данных задаём до обучения. Выбор checkpoint и гиперпараметров B0 выполняем на внутренней validation модели; финальную тестовую часть не используем. Данные для оценки селектора не должны становиться скрытой частью подбора B0. При ограниченном объёме данных применяем внутреннее разбиение/cross-fitting и документируем его.

После обучения:

- сохраняем checkpoint B0, предобработку и отображение классов;
- переводим B0 в eval, отключаем градиенты при сборе данных селектора;
- собираем опорную геометрию именно для этого checkpoint;
- при последующем изменении B0 пересобираем признаки, опорный банк и цели селектора.

Полное дообучение не является условием применимости геометрии: это выбранный режим подготовки модели. Для сравнения с готовыми весами нужен отдельный эксперимент, поскольку качество и геометрия признаков могут измениться.

### 17.2. С каких слоёв B0 берём информацию

Для стандартного MiT-B0 используем следующие точки. Размеры сеток ниже номинальные для входа с размерами, кратными соответствующему stride; реальные формы проверяем после padding. Конкретный decoder width зависит от реализации и checkpoint.

| Точка | Пространственная сетка | Каналы B0 | Для чего берём |
|---|---|---:|---|
| Выход стадии энкодера 1, F1 | Примерно H/4 × W/4 | 32 | Детали и границы; дополнительная абляция |
| Выход стадии энкодера 2, F2 | Примерно H/8 × W/8 | 64 | Промежуточные признаки; дополнительная абляция |
| Выход стадии энкодера 3, F3 | Примерно H/16 × W/16 | 160 | Более семантические признаки; дополнительная абляция |
| Выход стадии энкодера 4, F4 | Примерно H/32 × W/32 | 256 | Глубокая семантика, но грубая локализация |
| Слитая карта декодера перед финальным classifier, F_dec | Обычно сетка около H/4 × W/4 | D_dec из конфигурации | **Основной источник геометрии для первого селектора** |
| Логиты после classifier, Z_L | Нативная сетка головы | C | Вероятности, уверенность и окончательная маска после upsample |

Точные точки сверяем с forward выбранной реализации: часть библиотек возвращает только F1…F4, а F_dec нужно дополнительно сохранить hook или изменением forward. В eval нет нового случайного dropout; признаки фиксируем в точке непосредственно перед финальной классификацией в выбранной голове. Источник архитектуры: официальный SegFormer, определения `mit_b0` и многомасштабная MLP-голова; численные каналы проверяем в конфигурации используемого checkpoint.

**Для первой версии не складываем все слои в огромный вектор.** Берём p_L для уверенности и F_dec для геометрии. Это уже многомасштабно слитое представление с более подробной пространственной сеткой, чем F4. Затем проверяем, улучшает ли добавление F4 или нескольких стадий качество при учёте времени и памяти.

Для каждой новой точки строим отдельные прототипы и нормировки: нельзя сравнивать расстояния между F4 и F_dec как между векторами одного пространства. Опорные метки сопоставляем с сеткой признаков; ignore исключаем. Для тонких объектов nearest-neighbor downsample разметки может терять класс, поэтому отдельно проверяем долю покрытия и взвешенное построение статистик.

Точка для **вычисления геометрии селектора** не обязана совпадать с точкой **инъекции B2**. Например, селектор использует F_dec, а инъекция выполняется в F4 и затем повторяется декодер. Это не ошибка, но обе точки должны быть явно указаны.

### 17.3. Полный проход одного кадра до селектора

1. Предобрабатываем полный кадр точно как при обучении B0.
2. Один раз выполняем энкодер и декодер B0. Сохраняем p_L и F_dec; для инъекции также сохраняем нужные карты энкодера.
3. Получаем маску в координатах исходного кадра: argmax для Cityscapes или отдельные пороги для бинарных каналов.
4. Для каждого разрешённого класса выделяем восьмисвязные компоненты K.
5. Для каждой K строим область изменения A_K, кроп B_K и кольцо контекста R_K.
6. Переводим K, её границу, внутренность и кольцо на сетку F_dec с весами покрытия.
7. Вычисляем геометрические карты по фиксированным опорным статистикам и агрегируем их по компонентам.
8. Формируем X_K и предсказываем пользу и время.
9. Выбираем набор компонент с учётом λ и политики бюджета.
10. Только после выбора запускаем B2 и выполняем заранее определённое действие.

Можно считать геометрические расстояния сразу для всей сетки F_dec, а затем агрегировать. Можно считать их только в ячейках, покрытых кандидатами. Это две реализации с одинаковой целью; измеряем, какая быстрее. Признаки окружения требуют также покрыть кольца. Стоимость построения всех входов селектора оплачивается до решения и входит в общий бюджет, даже если B2 не запустится ни разу.

### 17.4. Конкретный вход селектора: одна компонента — один вектор

Предлагаемый стартовый набор для многоклассовой задачи ниже. Все непрерывные величины стандартизируем по train селектора. Число признаков — выбор этой реализации, а не требование статьи.

| Блок | Состав | Число |
|---|---|---:|
| Класс | One-hot по C классам | C |
| Форма | Доля площади K, относительные ширина и высота bbox, fill, log отношения сторон | 5 |
| Планируемый запуск | Доля площади B_K, высота и ширина реального входного тензора B2 | 3 |
| Уверенность по K | Среднее и q90 для энтропии, VR и отрицательной маржи −PM | 6 |
| Граница и внутренность | Средняя энтропия и средняя VR для каждой из двух областей | 4 |
| Окружение R_K | Средняя энтропия и средняя VR | 2 |
| Геометрия по K | Среднее и q90 для s_near и s_pred | 4 |
| Геометрия по окружению | Среднее s_pred в R_K | 1 |
| Признаки пустых областей | Нет внутренности, нет кольца | 2 |

Итого базовый вариант без геометрии: **C+22** признака. Геометрический: **C+27**. Для стандартной дорожной схемы C задаётся отображением классов выбранного датасета/checkpoint. Trust Score добавляем отдельной абляцией, например ещё два агрегата. Прогноз стоимости T̂_K вычисляется отдельной функцией и участвует в решении; его также можно добавить одинаковым дополнительным признаком обоим селекторам, тогда размер обоих входов увеличится на один.

Граница, например, определяется как K без её эрозии, внутренность — эрозия K. Толщину фиксируем. Для тонкой компоненты внутренность может быть пустой: ставим согласованное значение статистики и флаг пустоты, а не делим на ноль. Аналогично обрабатываем пустое кольцо у границ кадра.

**На вход не подаём:** GT, истинную ошибку B0, ответ B2 или истинную пользу G_K. Эти величины используются только как обучающие цели и для проверки. Не подаём сырой массив всех токенов разной длины: выбранный табличный селектор получает фиксированный вектор агрегатов.

База и геометрическая версия получают одинаковые признаки формы, контекста и размера кропа. Поэтому выигрыш геометрической версии нельзя объяснить тем, что только ей сообщили площадь.

### 17.5. Как строим датасет селектора

Для каждого обучающего кадра и каждой его допустимой компоненты сохраняем:

$$\mathcal D_{sel}=\{(X_K,G_K,\widehat T_K,\mathrm{image\_id})\}.$$

X_K получен только из B0 и заранее заданного планирования. G_K получен с разметкой через **реальное** действие B2: тот же кроп, resize, контекст и способ сборки, что будут в runtime. Для инъекции используем уже обученный и замороженный адаптер.

Разделяем train/validation/test по image_id или сценам. Компоненты одного изображения не разбрасываем между split: иначе похожие признаки и один контекст попадут и в обучение, и в проверку.

Первый селектор:

$$\widehat G_K=w^\top\widetilde X_K+b,$$
$$\mathcal L(w,b)=\frac1M\sum_K(\widehat G_K-G_K)^2+\rho\|w\|_2^2.$$

Здесь X̃_K — стандартизированный вход; w и b — обучаемые параметры; ρ — регуляризация, подбираемая внутри train/validation. Выход может быть отрицательным, поскольку B2 может вредить. Сигмоида здесь не нужна: мы предсказываем величину изменения ошибки, а не вероятность.

Если кадры с сотнями компонент доминируют над остальными, явно выбираем веса обучения: равный вес компоненты или суммарно равный вес кадра. Это разные цели; при равном весе кадра каждому его кандидату можно назначить вес, обратный числу кандидатов. Сравниваем методы при одной и той же схеме весов.

После линейного baseline можно попробовать небольшой MLP или бустинг при неизменном протоколе. Это проверка нелинейности, отдельная от проверки геометрии.

### 17.6. Как учитываем нагрузку до запуска B2

Нагрузка здесь означает измеренные дополнительные вычисления, а не только размер компоненты. Сохраняем три уровня:

1. **Геометрия:** |K|, |A_K|, |B_K|.
2. **Реальный вход:** h'_K×w'_K после resize/padding, число кропов и batch policy.
3. **Ресурсы:** прогноз и измерение времени, память; при необходимости FLOPs.

Пример: две компоненты одинаковой площади могут иметь разные bbox. Длинная диагональная компонента приводит к большему прямоугольнику и более дорогому запуску, если сохраняем разрешение. Если оба кропа приводим к одному фиксированному входу, стоимость модели примерно одинакова, но степень потери деталей различается.

Для таблицы времени заранее выполняем пробные запуски B2 на допустимых размерах с тем же устройством, dtype и batching. Прогреваем модель, повторяем измерения и строим T̂_K. Это профилирование не использует тестовую разметку.

В runtime не запускаем B2 ради измерения стоимости решения, которое ещё только принимаем. Используем таблицу или модель времени. Реальную задержку фиксируем после выполнения для отчёта.

Польза для ошибок с нормировкой на весь кадр:

$$G_K=\frac{|A_K\cap V|}{|V|}\,\delta_K,$$

где δ_K — разность долей ошибок лёгкого и дорогого действия внутри A_K. Следовательно, площадь уже включена в G_K. Цена:

$$\lambda\widehat T_K.$$

**Дополнительно умножать ни G_K, ни λT̂_K на площадь не надо.** Если специально переопределяем цель как улучшение на единицу площади, это уже другая постановка, которую нужно согласовать с бюджетом и итоговой метрикой.

Для инъекции к обработке B2-кропов добавляется общая цена активации ветки: адаптер и повторный декодер. Полезно записать:

$$\widehat T_{extra}(S)=\mathbf1[S\ne\varnothing]T_{activation}+\widehat T_{variable}(S).$$

T_activation — обязательные операции при любом непустом наборе; variable — кропы, перенос и прочие зависящие от набора операции. Не начисляем полный повторный декодер отдельно каждой компоненте, если он запускается один раз после всех инъекций.

Поэтому индивидуальное правило Ĝ_K>λT̂_K — первый приближённый роутер. Для инъекции окончательную настройку обязательно делаем по **совместному полному времени**, включая общую активацию. Более точный планировщик сравнивает суммарную ожидаемую пользу набора с ценой всего набора; при взаимодействиях нужны оценки G(S), а не только сумма Ĝ_K.

### 17.7. Полный пример выбора λ под 25 мс

λ не вычисляем одной универсальной формулой: проверяем значения на validation и выбираем лучшее качество среди допустимых по бюджету.

Фиксируем:

$$G_K=C_L(K)-C_H(K),\qquad T_K=\text{дополнительное время действия},$$
$$\text{выбрать }K\iff\widehat G_K>\lambda\widehat T_K.$$

Если λ=0,001 единицы пользы/мс и кроп стоит 5 мс, его выбираем при Ĝ_K>0,005. Это единицы выбранной ошибки; не обязательно Dice. Равенство не выбирает компоненту при строгом знаке >; правило обработки равенств фиксируем.

**Все числа следующей таблицы условные и не являются замерами проекта.** Бюджет — среднее полное время ≤25 мс на кадр.

| λ | Среднее полное время | Итоговый Dice | Укладывается? |
|---:|---:|---:|---|
| 0 | 40 мс | 0,88 | Нет |
| 0,0005 | 29 мс | 0,87 | Нет |
| 0,001 | 24 мс | 0,86 | Да |
| 0,002 | 18 мс | 0,83 | Да |

Выбираем λ=0,001, поскольку среди допустимых точек у него лучший Dice. Для дорожного эксперимента в этой же процедуре основной метрикой выбираем mIoU.

$$\lambda^*=\underset{\lambda:\ \overline T_{val}(\lambda)\le25\,\mathrm{мс}}{\arg\max}\ Dice_{val}(\lambda).$$

Практическая процедура:

1. Обучить регрессию Ĝ_K один раз и зафиксировать её.
2. Получить scores и прогнозы стоимости для всех validation-компонент.
3. Взять сетку λ, например по квантилям положительных отношений Ĝ_K/T̂_K, плюс крайние режимы. Это удобная сетка кандидатов, а не гарантия нахождения оптимального набора.
4. Для каждого λ выполнить выбор компонент и сборку результата по той же политике, что в runtime.
5. Измерить полное время и финальный Dice/mIoU. Для дешёвого предварительного отбора можно использовать кэш, но время кэшированного запуска нельзя выдавать за время настоящего каскада. Финалистов измерить end-to-end.
project_components_token_injection6. Выбрать допустимую точку с лучшим качеством; если пограничная задержка нестабильна, проверить повторы и заранее согласованный запас до лимита.
7. Зафиксировать λ, адаптер, селектор, контекст и batch policy. Только затем оценить test.

Если λ входит в cost-sensitive логистическую loss из §8, для каждого λ обучаем отдельный rejector. Нельзя описывать эту процедуру как «один раз обучили Ĝ и поменяли порог»: это другая модель обучения.

Средний бюджет допускает отдельные медленные кадры. Если нужен лимит на каждый кадр или p95, меняем критерий и добавляем планировщик/ограничитель, а не называем среднюю задержку строгой гарантией.

### 17.9. Что именно проверит первый законченный эксперимент

**Вход:** полный кадр. **Выход B0:** вероятности и карта признаков перед classifier. **Кандидаты:** компоненты предсказанных классов. **Вход селектора:** фиксированный вектор статистик каждой компоненты, её окружения и будущего кропа. **Цель обучения:** реальная польза определённого дорогого действия. **Управление нагрузкой:** λ и прогноз времени, затем проверка полного времени. **Ответ системы:** маска после выбранных замен или инъекций.

Успех основной гипотезы — геометрический селектор даёт лучшее итоговое качество при сопоставимом полном времени, чем такой же селектор без геометрии. Успех инъекции — она улучшает этот компромисс относительно замены вероятностей после учёта адаптера, повторного декодера и памяти. Ни один из этих результатов заранее не предполагаем.
