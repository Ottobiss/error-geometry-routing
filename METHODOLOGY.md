# Методология: работа с табличными данными

Черновик от 2026-10-24. Признаки на уровне компонент и патчей считаем зафиксированными; дальше —
обучение и анализ на одной таблице признаков, без GPU.

## 1. Что уже установлено (из EXPERIMENTS.md)

- В домене (CS P1) ни одна оценка B0 не лучше энтропии: ни по отдельности (MD по выходу +0.48
  [−0.15, +1.21] @20% — лучшая точечная оценка), ни в обученном регрессоре (геометрия к регрессии на
  энтропии ничего значимого не добавляет: DDU +0.38 [−0.06, +1.06], kNN −0.16).
- При сдвиге (ACDC) место для роутера больше (оракул − энтропия +5.55 против +2.60 на CS; энтропия
  берёт 31% выигрыша оракула против 64%), но Spearman всех оценок с Δ ≤ 0.10. Единственный значимый
  плюс — MD по выходу B0 @20%, +0.65 [+0.09, +1.22], пограничный.
- Патчи 256 + контекст 64: обученный роутер (энтропия / уверенность / +MD / +геометрия; CS P0, ACDC LOCO)
  не лучше энтропии ни при k на кадр, ни при общем бюджете.
- Рабочий рычаг — распределение бюджета **между кадрами** (общий порог), а не выбор регионов внутри
  кадра: +0.6…+1.2 на CS.

Следствие для следующего этапа: вопрос «предсказывает ли геометрия Δ региона лучше энтропии» в текущей
постановке в основном закрыт отрицательно. Табличный этап должен (а) аккуратно добить его условным
анализом и (б) проверить другие цели, где геометрия может работать: уровень кадра и сдвиг (§6).

## 2. Таблица признаков

Одна таблица на единицу: `results/tabular/components.parquet` и `results/tabular/tiles.parquet`.
Строка — компонента (или патч) CS P0 / P1 и ACDC; столбцы:
- ключи: `dataset`, `population` (p0 / p1 / fog / night / rain / snow), `image_id`, `comp_id` и
  `class_id` (у патчей — `tiles`, `tile`);
- признаки с префиксом группы, чтобы наборы выбирались по префиксу: `conf_` (уверенность B0), `shape_`,
  `cls_` (класс B0), `ms_` (MetaSeg), `md_` (MD по выходу B0: mean / p90 / frac), `maha_` (shared / class),
  `ddu_`, `knn_`, `proto_`; у патчей — `conf_`, `shape_`, `cls_` и `m_` (оценки методов, перенесённые с
  компонент); эмбеддинги — по флагу `--emb` (`emb_*`, 256 столбцов);
- цели и веса: `delta`, `n_valid`, `has_valid`, `y_fail` — в признаки не попадают.

Сборка — `python -m features.export` (~5 мин: MD по выходу пересчитывается по логитам на GPU, остальное
склеивается из готовых parquet). Компоненты: 118 776 × 202, патчи: 8 872 × 39. Признаки, подогнанные на
CS P0, на строках P0 посчитаны на выборке подгонки. mIoU роутинга по-прежнему считается существующим
кодом оценки (`core.evaluation`, `routing.tile_router`).

## 3. Цели

- Основная: `delta / n_valid` (выигрыш B2 на размеченный пиксель), вес `n_valid`; единицы без
  разметки (`n_valid = 0`) в обучение не идут, при роутинге участвуют.
- Вспомогательные: `delta > 0` (бинарная, для AUROC/AP), `y_fail` (воспроизведение Kang et al.).
- Уровень кадра (новая): выигрыш кадра от B2 = mIoU-вклад кадра при замене целиком, и выигрыш лучших
  k патчей кадра — для распределения бюджета между кадрами.

## 4. Разбиения и подбор

- Обучение — только CS P0. Подбор гиперпараметров и выбор признаков — GroupKFold по `image_id`
  внутри P0 (5 фолдов, сид 0). CS P1 и ACDC для выбора не используются.
- Тесты: CS P1 (домен), ACDC fog / night / rain / snow / all (сдвиг).
- LOCO на ACDC — отдельный протокол («есть размеченные данные со сдвигом»), не смешивается с главным.
- Перед первым запуском на ACDC — короткая запись в журнале с главными сравнениями (как в разделе
  «Сдвиг домена»); всё остальное описательное.

## 5. Сравнения и статистика

- Опорные строки в каждой таблице: random, entropy, oracle, только B0, только B2.
- Чтобы отделить вклад признаков от вклада обучения, каждый обученный метод сравнивается с **той же
  моделью на одной энтропии** (контроль), а не только с сырой энтропией. Наборы признаков вложенные:
  энтропия ⊂ уверенность ⊂ +MD ⊂ +геометрия.
- Режимы бюджета: доля пикселей / k на кадр (внутри кадра) и общий бюджет по набору (между кадрами);
  главным считаем общий бюджет.
- Парный bootstrap по кадрам, 2000 повторов, сид 0; интервал 95% для разницы mIoU с контролем.
  Число главных сравнений ограничено заранее; без поправки граничные результаты помечаются как такие.
- Модели — лёгкие: логистическая/линейная регрессия на стандартизованных признаках, HistGBR
  (как сейчас). Всё детерминировано (`random_state` у всех моделей, в том числе в `baseline/failure.py`).

## 6. Гипотезы этапа (в порядке приоритета)

1. **Условная информация.** Несёт ли геометрия информацию о Δ при фиксированной энтропии: частичная
   корреляция и Spearman внутри децилей энтропии; прирост лог-правдоподобия / AUROC `delta > 0` от
   добавления группы на фолдах P0. Дешево и отвечает на главный вопрос напрямую, без роутинга.
2. **Распределение бюджета между кадрами.** Агрегаты по кадру (доли/квантили признаков) → выигрыш
   кадра; роутер = порог на кадр + энтропия внутри кадра. Здесь у нас уже есть найденный рычаг.
3. **Детектор сдвига как гейт.** Геометрия хорошо отличает «не как на P0» (kNN, DDU — это их прямая
   задача). Проверить: AUROC «кадр из ACDC против CS P1» по группам признаков; правило «кадр далёк от
   P0 → B2 на кадр целиком» против энтропии при том же среднем времени.
4. **Типология ошибок (описательная).** Ошибки на границах (доля `boundary_size`) против ошибок
   «вне многообразия» (низкая энтропия при большом kNN/DDU-расстоянии); как доли и Δ этих типов меняются
   CS → ACDC и по условиям.

## 7. Организация кода и записей

- Сборка таблиц — `features/export.py`; эксперименты читают только `results/tabular/`.
- Эксперимент = конфиг (единица, признаки, модель, цель, обучение, тест, режим бюджета) →
  `results/tabular/runs/<имя>/` с `config.json`, `scores.parquet`, `metrics.json`.
- Журнал — новый раздел EXPERIMENTS.md «Табличный этап».
